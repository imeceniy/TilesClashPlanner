# Raster Map Graph — project-aware skill

## Trigger
Use when asked to vectorize a raster territory map, infer graph passages, or integrate map JSON in React + TypeScript + Konva.

## Safety and operating contract
1. **Inspect before creating**: read `package.json`, project map loader, definitions of `MapData`, `Territory`, `TerritoryConnection`, example map JSON, event rules, palette/types, test commands, and map asset/catalog structure. Run `rg -n 'interface (MapData|Territory|TerritoryConnection)|type (MapData|Territory|TerritoryConnection)|loadMap|mapCatalog' .` (exclude node_modules/dist). Record paths, shapes, IDs, coordinate conventions, reward schema, whether graph edges are directed, and how inactive/decorative regions are represented. **Do not assume this package's example schema equals project schema.**
2. Respect any existing project conventions, instructions, plans, or migration rules. Never overwrite existing maps, project plans, images or source files unless explicitly requested. Choose a new candidate map directory and write into staging first.
3. Inputs: immutable raster image, labeled-mask image of *same exact dimensions* (or carefully derived segmented labels), `regions.json` mapping pixel colors to region type/active status/reward proposals, `rules.json` describing allowed traversals/portals, and optional existing map for ID reconciliation.
4. Before extracting polygons, assess reliability of segmentation: ambiguous colors, tiny/fragmented regions, text/lines covering boundaries, islands, missing classification, blur, occlusions, borders. **Do not invent** uncertain territory boundaries, IDs, rewards, or passages. Add a structured `review.json` entry and block ready-for-production on unresolved blocking issues.
5. Use one **planar shared-boundary topology**: polygonize the *single labeled segmentation* (not independently drawn polygons). Thus neighboring areas share the same underlying raster grid edges; image pixel coordinate origin top-left, x right, y down, units pixels. Keep image width and height unchanged. Do not rescale, recenter or simplify polygon chains without topology-preserving shared-edge operation. Preserve holes and multipart geometries, or flag incompatibility if target renderer only accepts a single ring.
6. Territory centers must be guaranteed interior label points (`representative_point`), not necessarily centroid. Write explicit centroid separately only if project requires it. Coordinates are at original image size.
7. Adjacency ≠ traversability. Derive `adjacent` candidate pairs from shared border length; only export passable edges when `rules.json` or explicit manual decision approves them. Point-touch alone is not traversable. Inactive/decorative regions must not accidentally become passable nodes.
8. Stable IDs: old-map matching by mask/polygon intersection-over-union *plus* type/active checks. Reuse ID only for a unique, unambiguous one-to-one match above threshold. Split/merge/type change/duplicate candidate => review required. New IDs from explicitly bound stable `key`; never assign by scan order/centroid or automatic random ID. See `scripts/build_map.py`.
9. Validate duplicate territory IDs, duplicate edge IDs/pairs, missing endpoints, invalid geometry, out-of-bounds points, area gaps/overlap, intended shared boundaries, inactive edges, non-connected components and any required hub/root connectivity. Distinguish errors from warnings, always emit diagnostics.
10. Generate `map.candidate.json`, `review.json`, `preview.html`, `validation.json`; deliver only as **candidate** until both ambiguity queue cleared and project checks pass. Use `scripts/build_map.py` and `scripts/validate_map.py`.
11. Project adapter: the generated JSON here is **canonical intermediate format**, not automatically compatible with `MapData`. Inspect actual TypeScript contracts, write a deterministic adapter for exact project fields (territory type enums, center, polygon, reward, and `TerritoryConnection` shape); never create unknown properties speculatively. Import candidate into actual project loader and run project's own commands: TS typecheck, lint, map tests, and production build; discover them in `package.json`, do not invent commands. Report pass/fail/commands and any unsupported requirements.
12. For preview, use a single HTML page generated by `render_preview.py` using Konva.js (can reference vendor dependency/CDN; warn that CDN needs network). Overlay original map, traced borders, IDs, edges (approved solid; candidates dashed) and hover metadata. HTML is a review utility and does not replace project tests.

## Minimal commands
For Winter's color-by-type mask, use `scripts/build_two_image_map.py` from the project root. It separates disconnected components of each palette color, verifies the 168-cell type counts against the aligned ID reference, and writes persistent type-prefixed IDs and native project JSON. The reference alignment is recorded in the script. Rewards are unknown and remain zero until supplied. Border-gap adjacency is generated using a 10px maximum gap and buffered shared-border area over 100px²; inspect this candidate graph visually before treating routes as confirmed. Corner-only contacts are excluded by the area threshold. The original generic mask builder remains available for fully labeled masks.

```bash
python scripts/build_map.py --image source.png --mask mask.png --regions regions.json --rules rules.json --out staging/new-map [--previous staging/previous-map.json]
python scripts/validate_map.py staging/new-map/map.candidate.json --report staging/new-map/validation.json
python scripts/render_preview.py staging/new-map/map.candidate.json --image source.png --output staging/new-map/preview.html
```
`pip install -r requirements.txt` if necessary. Example config in `examples/`.

## Data model and review policy
Canonical `map.candidate.json`: `schemaVersion`, `image:{src,width,height,sha256}`, `territories:[{id,key,type,active,decorative,rewards,center,geometry:{type:"Polygon"|"MultiPolygon",coordinates:[...]}}]`, `adjacencies:[{a,b,borderLength}]`, `connections:[{id,from,to,kind:"passage"|"portal",directed?}]`, `reviewRequired`, `metadata`. Polygon is GeoJSON ring structure in original pixel coordinates. For `Polygon`, coordinates = [exterior, ...holes]; for `MultiPolygon`, coordinates = [[exterior,...holes],...].

`review.json`: `{issues:[{code,severity,regionIds?,bbox?,message,action}], blockingCount}`. Every uncertain passage, conflict in IDs, unclassified color, thin border/corner ambiguity, type mismatch, nonmatching reward, hole, unsupported multipart, and edge endpoint issue must be made visible. `severity:"blocking"` prevents production. When no mask or inputs provided, do not fabricate generated map: request/derive a candidate segmentation and present unresolved areas.

## Completion checklist
- Exact input pixel dimensions and image SHA.
- All region types and rewards sourced or explicitly undecided.
- Positive area and valid geometries, shared boundaries consistent.
- IDs stable and unique; split/merge reviewed.
- Graph passages confirmed, no decorative traversals, connected-component analysis reported.
- Candidate overlay aligned with original raster.
- Project-native adapter and real npm scripts pass; existing artifacts untouched.

## Read-only project reconnaissance
Run `python scripts/inspect_project.py /path/to/project --output /tmp/map-project-inspection.json`. Review type-definition excerpts manually, especially imports/aliases and serializers. Do not use script guesses as an adapter. If project uses Vite/webpack, use its own loader path for image URLs. For a preview without network, copy an approved local `konva.min.js` build and change the script source; do not alter the visualizer's geometry.

## Tests for this skill
`python -m unittest discover -s tests -v` — synthetic map examples in `examples/` exercise duplicates, missing endpoints, overlaps, inactive edges and disconnected graph. These do **not** replace application tests.

## Project-output manifest
When working in an actual repository, provide a manifest containing source map path, staged JSON, adapter path, Konva HTML, `review.json`, validator report, and commands run with exit codes. Block final integration if review issues remain or TS/lint/map tests/build failed; never report unrun checks as green.
