# Техническое задание

## 1. Название проекта

Веб-приложение для планирования стратегии захвата карты в событиях **Gene Clash / Oil Clash / аналогичных Clash-событиях игры Tiles Survive**.

Рабочее название проекта можно использовать:

**Tiles Clash Planner**

Основная задача приложения — дать офицерам союза простой визуальный инструмент, в котором можно один раз в день быстро обновить фактическую ситуацию на карте, отметить приоритеты, направления движения и получить готовую наглядную карту-план для распространения среди участников союза.

---

# 2. Основная идея

Приложение должно отображать интерактивную карту события Tiles Survive.

Пользователь должен иметь возможность буквально за несколько минут:

1. отметить уже захваченные союзом территории;
2. отметить территории противника;
3. отметить территории, которые были потеряны;
4. назначить цели на текущий день;
5. разделить цели по приоритету;
6. указать направление продвижения стрелками;
7. отметить стартовую позицию своего союза;
8. отметить стартовые позиции/зоны союзов противника;
9. сохранить состояние;
10. получить готовую картинку с планом на день.

Ключевая концепция:

> Открыли карту → несколько раз кликнули → получили план на день.

Приложение не должно превращаться в сложный игровой калькулятор. На первом месте — **простота, скорость и визуальная наглядность**.

---

# 3. Основные требования заказчика

За основу интерфейса необходимо принять следующие требования:

- захваченная территория — **зелёная**;
- главный приоритет — **красный**;
- второстепенная цель / «постараться взять» — **жёлтая**;
- названия объектов, например `M30`, должны быть очень хорошо видны;
- логова должны визуально отображаться **кругами**;
- верстаки должны визуально отображаться **квадратами**;
- направление движения должно отмечаться стрелками;
- карту предполагается обновлять ежедневно;
- ненужную территорию должно быть легко вернуть в нейтральное состояние;
- если противник отобрал территорию, пользователь просто меняет её состояние;
- очки и дополнительная статистика вторичны;
- название объекта всегда важнее всех остальных подписей;
- если отображаются очки — они должны быть существенно меньшим шрифтом.

# 4. Исходная карта

В качестве источника структуры карты использовать Excel-шаблон:

`Битва за нефть 8 (2).xlsx`

Файл содержит расположение объектов и фактически представляет координатную схему игровой карты.

Необходимо на первом этапе вручную или программно перенести расположение объектов из Excel в структуру данных приложения.

Карта должна сохранять взаимное расположение объектов максимально близко к исходному Excel-шаблону.

# 5. Типы объектов

На карте существуют два основных типа объектов.

## 5.1. Логова

Обозначаются **кругом**.

Используются следующие размеры/типы:

- `XS`
- `S`
- `M`

Объекты имеют уникальные идентификаторы, например:

- `XS12`
- `S3`
- `M30`

Название должно отображаться **крупно и контрастно внутри или рядом с объектом**.

Базовые значения из текущего Excel-шаблона:

| Тип | Базовое значение |
|---|---:|
| XS | 80 |
| S | 160 |
| M | 200 |

Эти значения являются вторичной информацией.

На карте по умолчанию их можно:

- не показывать;
- либо показывать маленьким шрифтом под названием;
- либо включать через настройку `Показывать очки/ценность`.

---

## 5.2. Верстаки

Обозначаются **квадратом или прямоугольником с небольшим скруглением**.

Типы:

- `S`
- `M`
- `L`
- `XL`
- `XXL`

Базовые значения из Excel:

| Тип | Базовое значение |
|---|---:|
| S | 240 |
| M | 320 |
| L | 480 |
| XL | 800 |
| XXL | 1600 |

Название объекта должно быть визуально главным элементом.

Например:

**XL4**

ниже маленьким:

`800`

# 6. Состояния территорий

Каждый объект карты должен иметь поле `status`.

Минимальный набор состояний:

### neutral
Нейтральный объект.

Отображение:

- серый;
- либо белый/прозрачный;
- чёткая граница.

### captured
Уже захвачено нашим союзом.

Цвет:

**зелёный**

Смысл:

> То, что уже забрали.

---

### priority
Главная цель на текущий день.

Цвет:

**красный**

Смысл:

> Взять в первую очередь.

---

### secondary
Второстепенная цель.

Цвет:

**жёлтый**

Смысл:

> Не основной приоритет, но желательно взять.

---

### enemy
Контролируется противником.

Предлагаемый цвет:

**фиолетовый / синий / оранжевый**, в зависимости от конкретного противника.

Важно:

для противников желательно использовать не один общий цвет, а назначать каждому союзу свой цвет.

---

### blocked / ignore

Опциональное состояние.

Для объектов, которые в текущем плане не рассматриваются.

Можно отображать:

- тёмно-серым;
- с уменьшенной прозрачностью.

---

# 7. Управление объектами

Главный принцип:

> Для изменения состояния территории должно требоваться минимальное количество действий.

## 7.1. Обычный клик

При клике по территории открывается небольшое context menu / popup.

Например:

**M30**

- ✅ Захвачено
- 🔴 Приоритет
- 🟡 Вторичный приоритет
- 👥 Противник
- ⚪ Нейтрально
- 🚫 Не учитывать

Не открывать полноценное большое модальное окно для простой смены состояния.

# 8. Быстрый режим раскраски

Обязательно добавить режим «кисти».

В верхней панели:

**Инструмент:**

- Выбор
- Захвачено
- Приоритет
- Вторичная цель
- Противник
- Нейтрально
- Стрелка
- Текст

Пользователь выбирает, например:

`🔴 Приоритет`

и после этого последовательно кликает по нужным территориям.

Каждый клик сразу делает выбранную территорию красной.

Это критически важно для быстрого ежедневного обновления карты.

# 11. Направления атаки

Одна из ключевых функций.

Пользователь должен иметь возможность рисовать стрелки между территориями.

Пример:

`M12 → M18 → XL3`

Стрелка должна задаваться:

1. выбрать инструмент `Стрелка`;
2. кликнуть стартовую территорию;
3. кликнуть конечную территорию.

После этого рисуется линия со стрелкой.

# 12. Настройки стрелки

Для каждой стрелки желательно поддерживать:

```ts
Arrow {
  id: string
  fromTerritoryId?: string
  toTerritoryId?: string

  fromX?: number
  fromY?: number
  toX?: number
  toY?: number

  color: string
  width: number
  dashed: boolean

  label?: string
}
```

Цвет стрелки можно выбирать:

- красный — главный удар;
- жёлтый — дополнительное направление;
- зелёный — развитие уже занятой территории;
- другой цвет — пользовательский.

# 16. Внешний вид карты

Карта должна быть аккуратной, но не перегруженной.

Основные требования:

- тёмный или нейтральный фон;
- высокий контраст объектов;
- крупные названия;
- отсутствие мелких декоративных деталей;
- стрелки должны быть хорошо заметны;
- карта должна нормально выглядеть в экспортированной PNG.

Название объекта:

**главный визуальный приоритет.**

Например:

```text
┌──────────┐
│   XL4    │
│   800    │
└──────────┘
```

где `XL4` условно 18–24 px, а `800` 10–12 px.

# 34. Drag & Drop

Статические игровые объекты не должны случайно перемещаться пользователем.

То есть:

- территория имеет фиксированные координаты;
- карту можно перемещать;
- подписи можно перемещать;

# 45. Требования к читаемости

Особое внимание уделить названиям.

На карте одновременно может находиться большое количество:

- M1
- M2
- M3
- S1
- XL1
- и т. д.

Поэтому:

- текст не должен сливаться с фоном;
- использовать outline / text shadow;
- название должно быть видно поверх любого цвета объекта;
- не использовать слишком тонкий font-weight;
- название должно оставаться читаемым на экспортированной картинке.

Например:

```css
font-weight: 800;
text-shadow:
  -1px -1px 0 #000,
   1px -1px 0 #000,
  -1px  1px 0 #000,
   1px  1px 0 #000;
```

# 46. Цветовая схема по умолчанию

Использовать примерно:

```ts
neutral   = gray
captured  = green
priority  = red
secondary = yellow
ignore    = dark gray
```

Не завязывать бизнес-логику на конкретные HEX-коды.

Все цвета должны находиться в theme/config.

# 54. Отдельная задача: импорт карты из Excel

Не рисовать карту вручную прямо в React-компоненте.

Необходимо преобразовать Excel-шаблон в структурированный dataset.

Например:

```text
scripts/
└── parse-map.xlsx.ts
```

Результат:

```text
src/data/gene-clash-map.json
```

Excel использовать как источник координатной структуры.

Нужно определить:

- координату строки;
- координату столбца;
- название объекта;
- тип объекта;
- размер;
- базовое значение.

Далее преобразовать Excel grid coordinates в координаты canvas.

Например:

```ts
x = columnIndex * CELL_WIDTH
y = rowIndex * CELL_HEIGHT
```

После первоначального импорта приложение должно работать уже с JSON, а не читать Excel при каждом запуске.

# 58. Основной принцип разработки

Не пытаться сделать «красивую игровую карту» в ущерб удобству.

Это **рабочий тактический инструмент для R4/R5**, который каждый день должен позволять за несколько минут превратить текущее состояние карты в понятный план для всего союза.

Приоритеты продукта:

**скорость работы → читаемость → простота → наглядность → аналитика.**

Главный вопрос при проектировании любого элемента интерфейса:

> Сможет ли пользователь за один-два клика изменить план и сразу понять текущую стратегию?

Если нет — интерфейс следует упростить.
